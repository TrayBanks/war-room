# Slot 10 War Room

Tray's toolkit for **NBA League Revamped** on Sleeper: a Chrome extension (draft overlay + in-season Lock-In coach), the Python model that ranks players, and the reports built from it. Everything is read-only against Sleeper and acts only on Tray's click.

## League facts (don't re-derive these)

- League `1398532731020828672`, draft `1398532732564320256`, 10 teams, 14 rounds, 2-minute picks, snake. Tray picks **10th** (10, 11, 30, 31, 50, 51, …). Draft: **Sun Oct 18, 2026, 7:30 PM CT**. Sleeper user id `107261208461459456`. It's a cash league.
- Starters: PG, SG, G, SF, PF, F, C, UTIL, UTIL. Bench 5.
- Scoring (equals Sleeper's `pts_std`): pts 0.5, 3PM 0.5, reb 1, ast 1, stl 2, blk 2, TO −1, DD 1, TD 2.
- **Lock-In**: each starter counts ONE game per week (Mon–Sun). After a game you may lock it, but only before his next game tips. Unlocked, his last game of the week counts. Locks are permanent and tie the player to his slot. Only games he *started* can be locked.
- Regular season fantasy weeks 1–18, playoffs 19–21. NBA season starts 2026-10-20 (week 1).

## Commands

- `npm test` — all five suites (engine, lock, bridge, ui, season). Run after any change to extension/ or model/.
- `npm run build` — rebuild rankings and extension/data.js. Then `npm test`.
- `npm run render` — Playwright screenshots into reports/screens (Chromium at /opt/pw-browsers if present; otherwise set `executable_path`).
- `npm run lock -- "Jokić" 43 2 [even|chase|protect]` — lock or hold.
- `npm run replay -- <room sharpness 0..1> <seed> [slot]` — full draft following the panel: roster, position mix, engine ms per pick.
- `python3 tests/perf_live.py [extension_dir]` — real-Chromium jank check during a fast draft (frames over 50 ms, compute/paint ms). Keep frozen time near zero.
- `npm run package` — dist/slot10-war-room-v<version>.zip. Bump `version` in package.json and extension/manifest.json together.
- `python3 tools/fetch_sleeper.py [--add 260] [--schedule]` — refresh projections, ADP, injuries, teams.

## The live War Room page (refreshes itself)

- Live at https://traybanks.github.io/war-room/ (GitHub Pages, public repo TrayBanks/war-room). The claude.ai artifact "Slot 10 War Room" is a snapshot that links to it.
- `.github/workflows/refresh.yml` refreshes at 6 AM, 12 PM, 5 PM and 11:30 PM Central. GitHub delays and drops scheduled runs, so a gate job runs every 30 minutes and refreshes only when the live page's `status.json` is older than the latest slot (self-healing; DST handled in Central time). It also runs on manual dispatch and on pushes that touch the page code. It runs `tools/refresh.sh site`, deploys `site/` to Pages, and on Mondays commits `data/history/<date>.json` (a snapshot that also keeps GitHub from pausing the schedule after 60 quiet days).
- `tools/refresh.sh`: `sleeper_pull.js` (Sleeper → data/live/{league,extras,trending,week}_<ET date>.json) → `week_page.js` (This week card + live-week projection) → `season_report.js` twice (normal, and `WR_SD=30 WR_TAG=_wide`) → `trending.js` → `build_season_page.py <date> --site site`. `WR_DATE=YYYY-MM-DD tools/refresh.sh` reruns offline on saved files.
- Finished weeks use real scores (`league.results`), the current week uses week_page's projection for Tray's matchup, later weeks are simulated.
- Locks: Sleeper's API has no lock field. `data/locks.json` holds locks Tray told us about (`{"<week>": [player ids]}`); week_page.js also infers a lock once the player plays again; the page's "Mark locked" button stores marks on his phone (localStorage).
- The page template is `model/season_page/template_v2.html` (data injected at `/*__DATA__*/null`). Section tabs open a full-screen focus view; deep dives are folded by default (Tray wants ADHD-friendly, answer-first cards).
- Watch a run from Tray's PC: `gh run list -R TrayBanks/war-room`; trigger one: `gh workflow run refresh.yml -R TrayBanks/war-room`.

## The models in one paragraph each

**Lock value** (model/lock_value.py, extension/lock.js). Per-game score X = max(0, μ(1 + cv·Z)), Z from pooled standardized 2025-26 residuals (right-skewed). cv is shrunk toward the pool median (0.348) by sample size. With k games left and play probability q: V_k(c) = α_k·c + B_k, α_k = (1−q)^k, B_k = (1−q)B_{k−1} + q·E[max(X, V_{k−1}(X))]. Lock when c ≥ T_k = B_k/(1−α_k). Risk modes apply utility x^γ (chase 1.35, protect 0.75). Season lock value = E over the week's game count of the optimal-stopping value, with availability split into missed weeks vs rest days (load-managed vets rest more).

**Roster fit** (engine.js `fitModel`, v1.2). Value to Tray's lineup, not raw value: best assignment of his players to the 9 slots (bitmask DP over slots; a C-only player in UTIL counts 90%), plus 30% bench value for whatever doesn't start, scaled by slot flexibility (eligible slots / 5, clamped 0.6–1.2) and divided by 1 + 0.5 × (bench players already covering the same position groups). Recommendations and the default board sort use this. `npm run replay -- 0.65 1` replays a full draft following the panel; tests/test_fit.js asserts ≤ 2 center-only players and engine speed.

**Room sharpness** (engine.js `learnRoom`). Each manager's sharpness s ∈ [0,1] has a grid posterior, prior N(0.65, 0.22) because it's a cash league. A manager scores players by (1−s)·ADP rank + s·value rank, picks by softmax (τ = 2.5) with an 8% uniform blunder rate, so one bad pick barely moves s. Survival odds simulate the picks before Tray's turn 400 times, sampling each manager's s from his posterior.

## Rules for working here

- Never read or send Sleeper's auth token. The extension uses only `localStorage.user_id` and public API endpoints.
- Never click Draft, Queue, auto-pick or lock in Tray's real Sleeper account without his explicit go-ahead in chat. Live checks on sleeper.com are read-only: inspect, read computed styles, inject a static preview into a shadow root, remove it after.
- The extension never acts on its own: no auto-drafting, no auto-locking.
- Keep engine.js and lock.js DOM-free so they stay testable in Node.
- Speed budget: a new pick must not block the page. engine.compute is memoized on (picks, mode, slot, status); simulate is O(pool) per simulated pick; the panel writes the DOM only when markup changed (`setHTML`). Re-run tests/perf_live.py after touching any of these.
- bridge.js selectors were verified on the live classic room and beta draftboard on Oct 17, 2026. If Sleeper changes markup, fix bridge.js and tests/test_bridge.js; pick tracking (API) keeps working regardless.
- Design: the panels must read as part of Sleeper. Tokens in styles.js were sampled from the live pages (classic room: page #030616, side panel #283244, tabs #3A465B, NBA orange #FFAE58 for selected filters, indigo #6E7DF5 for selected tabs, Lato/Muli/Poppins; beta: DLS dark tokens). Re-sample before restyling rather than guessing.
- Copy in the UI: plain verbs, sentence case, say what a button does ("Queue my top 6", "I locked this in Sleeper").
